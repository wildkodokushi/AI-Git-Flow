# AI Git Flow

> [!WARNING]
> Эта утилита является экспериментальной и находится на ранней стадии разработки.

> [!NOTE]
> Буду рад вашим баг-репортам и Pull Request'ам!

> [!TIP]
> Есть кроссплатформенная версия на Node.js (Windows, macOS, Linux, несколько провайдеров моделей): [AI-Git-Flow-CLI](https://github.com/wildkodokushi/AI-Git-Flow-CLI). Она опубликована в npm и ставится одной командой:
>
> ```bash
> npx ai-git-flow init
> ```

Консольная утилита для Windows, которая автоматизирует рутину вокруг Git и оформления проекта. Тексты пишет GigaChat API, всё остальное делает сам скрипт.

После установки утилита запускается одним словом из любой папки репозитория:

```powershell
aiflow                      # ветка, коммиты, push и pull request
aiflow -Stay                # то же, но без новой ветки и без PR
aiflow readme               # сгенерировать README.md
aiflow license              # создать файл LICENSE
aiflow issue "описание"     # создать issue на GitHub
```

## Как это работает

Работа разделена между кодом и нейросетью.

- **Группировка файлов детерминированная.** Скрипт сам определяет тип каждого файла (зависимости, конфигурация, CI, стили, тесты, документация, ресурсы, исходный код) и собирает группы по правилам. Исходный код делится по каталогам верхнего уровня. Нейросеть не решает, какие файлы объединять, поэтому результат воспроизводим и не зависит от «настроения» модели.
- **Нейросеть пишет только текст.** Для каждой группы модель получает список файлов и сокращённый diff и возвращает одну строку с темой коммита. Для pull request модель формирует заголовок и краткое описание.
- **Скрипт устойчив к сбоям.** Если API недоступен или вернул мусор, подставляется шаблонное сообщение, и работа продолжается. Времена глаголов в темах нормализуются (`added` превращается в `add`).

Последовательность действий:

1. Анализ изменений в рабочей папке.
2. Формирование плана коммитов и генерация сообщений.
3. Показ плана и запрос подтверждения.
4. Создание ветки.
5. Коммиты по одному на группу.
6. Отправка ветки на сервер (`git push -u`).
7. Создание pull request через GitHub CLI.

## Требования

| Компонент | Зачем | Обязательно |
|---|---|---|
| Windows 10 или 11 с PowerShell 5.1 | запуск скрипта (PowerShell 5.1 уже встроен в Windows) | да |
| [Git](https://git-scm.com/) | работа с репозиторием | да |
| Ключ авторизации GigaChat API | генерация текстов | да |
| [GitHub CLI](https://cli.github.com/) (`gh`) | автоматическое создание pull request | нет |

## Установка

### Шаг 1. Получите ключ авторизации GigaChat

В личном кабинете разработчика Сбера откройте проект GigaChat API и перейдите в раздел «Данные для авторизации запросов к API». Нажмите «Получить новый ключ» и скопируйте значение поля **Authorization key**. Scope для физического лица: `GIGACHAT_API_PERS`. Он используется скриптом по умолчанию.

Ключ показывается один раз, поэтому сразу сохраните его (шаг 4). Никому его не передавайте и не добавляйте в репозиторий.

### Шаг 2. Установите утилиту

Скачайте папку проекта (файлы `ai-flow.ps1`, `install.ps1`, `README.md`) в любое место и выполните в PowerShell из этой папки:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Установщик:

- копирует `ai-flow.ps1` в `%LOCALAPPDATA%\Programs\ai-flow`;
- создаёт там файл запуска `aiflow.cmd`;
- добавляет эту папку в PATH текущего пользователя.

Права администратора не нужны. Политику выполнения PowerShell менять не требуется: файл запуска сам обходит её для этого скрипта.

### Шаг 3. Установите сертификат Минцифры

Серверы GigaChat используют сертификаты российского удостоверяющего центра, которому Windows по умолчанию не доверяет. Без сертификата скрипт сообщит, что не удалось проверить TLS-сертификат. Установить его проще всего через установщик:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -InstallCertificate
```

Windows покажет окно подтверждения, нажмите «Да». Сертификат устанавливается только для вашей учётной записи. Вручную то же самое делается так: скачайте корневой сертификат на странице https://www.gosuslugi.ru/tls и выполните

```powershell
Import-Certificate -FilePath .\russian_trusted_root_ca.cer -CertStoreLocation Cert:\CurrentUser\Root
```

Если ошибка не уходит, на той же странице скачайте и промежуточный сертификат и установите его командой выше в хранилище `Cert:\CurrentUser\CA`.

### Шаг 4. Сохраните ключ

Закройте терминал и откройте новый (в VS Code закройте окно целиком, иначе PATH не обновится). Затем выполните:

```powershell
aiflow -SetKey
```

Ключ вводится скрытно и сохраняется в переменную окружения пользователя `GIGACHAT_AUTH_KEY`. В файлы он не записывается. Если переменная не задана, скрипт спросит ключ при запуске, но тогда он будет действовать только на один запуск.

### Шаг 5. Подключите GitHub CLI (по желанию)

Нужен только для автоматического создания pull request:

```powershell
winget install --id GitHub.cli
gh auth login
```

Без `gh` утилита всё равно работает: ветка и коммиты создаются, а текст pull request выводится на экран для ручного создания.

### Проверка установки

```powershell
aiflow -Help
```

Должна появиться краткая справка.

## Первый запуск

1. Откройте терминал в папке репозитория с изменениями. В VS Code подойдёт встроенный терминал.
2. Посмотрите план, ничего не меняя:

   ```powershell
   aiflow -DryRun
   ```

3. Если план устраивает, запустите по-настоящему:

   ```powershell
   aiflow
   ```

   Скрипт покажет план, спросит подтверждение и имя ветки, после чего создаст ветку и коммиты, отправит их и создаст pull request.

## Повседневное использование

Типичный сценарий: вы поработали над задачей, в рабочей папке накопились изменения в разных файлах.

```powershell
aiflow -Branch feat/header-redesign
```

Другие примеры:

```powershell
aiflow -Lang ru -Draft                    # русские тексты, PR как черновик
aiflow -b fix/login-bug -y                # без подтверждения
aiflow -NoPr                              # ветка и коммиты, без PR
aiflow -NoPush                            # только локальные коммиты
aiflow -Base develop                      # PR в ветку develop
aiflow -dry                               # только показать план
```

Что важно знать:

- По умолчанию скрипт создаёт **новую** ветку от текущего состояния. Если ветка с таким именем уже существует, будет предложено ввести другое имя. Чтобы остаться в текущей ветке, на вопрос об имени введите точку (см. следующий раздел).
- Перед формированием плана индекс сбрасывается (`git reset`). Файлы в рабочей папке не меняются, но всё ранее добавленное через `git add` придётся добавить заново. Так коммиты собираются с нуля по единым правилам.
- Отправка выполняется обычным `git push -u`, без `--force`.
- Базовая ветка для pull request определяется автоматически (`origin/HEAD`, затем `main`, `master`, `develop`).

## Коммит без новой ветки

Иногда нужна просто пара коммитов и push в ветку, в которой вы уже работаете. Есть три способа:

1. На вопрос об имени ветки введите точку:

   ```text
   Текущая ветка: feat/header
   Имя новой ветки (например, feat/home-swiper). Напишите . чтобы остаться в текущей ветке: .
   ```

2. Параметр `-Stay` (или `-here`) пропускает вопрос: `aiflow -Stay`.
3. Параметр `-Branch .` даёт тот же результат.

В этом режиме скрипт делает коммиты по тем же правилам, отправляет их в текущую ветку (`git push -u`) и **не создаёт pull request**. В состоянии detached HEAD режим недоступен. Если вы остались в основной ветке (`main`), коммиты уйдут прямо в неё, поэтому внимательно читайте план перед подтверждением.

## Команды readme, license и issue

Команда указывается первым словом: `aiflow readme`, `aiflow license`, `aiflow issue`. Все они выполняются внутри репозитория и поддерживают `-DryRun` (показать результат, ничего не записывая) и `-Lang en|ru`.

Созданные файлы остаются в рабочей папке. Чтобы закоммитить и отправить их, выполните обычный `aiflow`: README и LICENSE попадут в группу документации.

### aiflow readme

Создаёт `README.md` по содержимому репозитория. Как и в основном режиме, работа поделена между кодом и моделью:

- **Код** определяет языки и технологии (по расширениям файлов и `package.json`), собирает команды установки и запуска из `scripts` и менеджера пакетов, рисует дерево проекта, подставляет адрес `git clone` (учётные данные из URL вырезаются) и добавляет раздел о лицензии, если есть файл `LICENSE`.
- **Модель** пишет только короткое описание проекта и список возможностей по дереву файлов и фрагментам ключевых файлов. В запросе указано не выдумывать функции, ссылки и значки. Если в `package.json` уже есть `description`, используется оно.

```powershell
aiflow readme -DryRun       # только показать результат
aiflow readme -Lang ru      # README на русском
aiflow readme -Force        # перезаписать существующий без вопроса
```

Если `README.md` уже существует, скрипт спросит разрешение на перезапись. Перед публикацией всегда читайте результат: модель могла неверно понять назначение проекта.

### aiflow license

Создаёт файл `LICENSE`. Текст лицензии **не пишет нейросеть**, он берётся из шаблонов, потому что юридический текст должен быть точным.

```powershell
aiflow license                           # выбор из списка
aiflow license -Type mit                 # без вопросов
aiflow license -Type apache-2.0 -Author "Иван Петров" -Year 2026
```

Доступные типы: `mit`, `apache-2.0`, `bsd-3-clause`, `bsd-2-clause`, `isc`, `gpl-3.0`, `agpl-3.0`, `lgpl-3.0`, `mpl-2.0`, `unlicense`. Допустимы сокращения (`apache`, `gpl`, `bsd`). MIT, BSD, ISC и Unlicense встроены в скрипт и работают офлайн. Остальные тексты загружаются с GitHub (`api.github.com`), поэтому нужен доступ к нему.

Правообладатель берётся из `-Author`, затем из `git config user.name`, иначе спрашивается. Год по умолчанию текущий.

Выбор лицензии остаётся за вами. Краткие пояснения в списке носят справочный характер и не являются юридической консультацией.

### aiflow issue

Превращает короткую заметку в структурированный issue и создаёт его через GitHub CLI.

```powershell
aiflow issue "Кнопка входа не реагирует на нажатие на телефоне"
aiflow issue "Добавить тёмную тему" -Labels enhancement,ui -Lang ru
aiflow issue "Обновить зависимости" -DryRun
```

Модель определяет тип (bug, feature или task), формулирует заголовок и тело по шаблону соответствующего типа. В запросе она получает вашу заметку, имя текущей ветки, последние пять тем коммитов и список файлов верхнего уровня. Неизвестные детали помечаются как «To be clarified», а не выдумываются. Метки подбираются автоматически (`bug`, `enhancement`) или задаются через `-Labels`. Если таких меток в репозитории нет, скрипт повторяет попытку без меток.

Перед созданием показывается предпросмотр и запрашивается подтверждение. Если `gh` не установлен или не авторизован, текст выводится на экран для ручного создания.

## Параметры командной строки

Регистр не важен. Параметры можно сокращать до уникального префикса.

| Параметр | Описание |
|---|---|
| `-Branch`, `-b` | Имя новой ветки. Если не указано, скрипт спросит. Значение `.` оставляет текущую ветку. |
| `-Stay`, `-here` | Не создавать ветку: коммит и push в текущую ветку, без PR. |
| `-Base` | Базовая ветка для pull request. |
| `-Remote` | Удалённый репозиторий. По умолчанию `origin`. |
| `-Lang` | Язык тем коммитов и описания PR: `en` (по умолчанию) или `ru`. Префиксы типов (`feat`, `fix`) всегда английские. |
| `-Model` | Модель для сообщений коммитов. По умолчанию `GigaChat-2`. |
| `-PrModel` | Модель для описания PR. По умолчанию `GigaChat-2-Pro`. |
| `-MaxCodeGroups` | Максимум групп для исходного кода (от 2 до 10, по умолчанию 5). Мелкие группы объединяются. |
| `-MaxDiffChars` | Сколько символов diff передавать модели для одной группы (по умолчанию 6000). |
| `-Draft` | Создать pull request как черновик. |
| `-NoPr` | Не создавать pull request. |
| `-NoPush` | Не отправлять ветку. Pull request тоже не создаётся. |
| `-DryRun`, `-dry` | Показать план или результат, ничего не менять. |
| `-Type` | `license`: тип лицензии. |
| `-Author`, `-Year` | `license`: правообладатель и год. |
| `-Text`, `-t` | `issue`: описание (можно передать вторым словом без имени параметра). |
| `-Labels` | `issue`: метки через запятую. |
| `-Force` | Перезаписать `LICENSE` или `README.md` без вопроса. |
| `-Yes`, `-y` | Не запрашивать подтверждение. |
| `-UseSystemProxy` | Использовать системный прокси. По умолчанию прокси для запросов к GigaChat отключён. |
| `-SkipCertCheck` | Отключить проверку TLS-сертификатов. Небезопасно, используйте только для диагностики. |
| `-SetKey` | Сохранить ключ авторизации GigaChat. |
| `-InitConfig` | Создать файл настроек по умолчанию. |
| `-Help` | Краткая справка. |

## Файл настроек

Чтобы не вводить одни и те же параметры, создайте файл настроек:

```powershell
aiflow -InitConfig
```

Файл находится по адресу `%APPDATA%\ai-flow\config.json`:

```json
{
  "Lang": "en",
  "Model": "GigaChat-2",
  "PrModel": "GigaChat-2-Pro",
  "Remote": "origin",
  "MaxCodeGroups": 5,
  "Draft": false
}
```

Поддерживаются ключи `Lang`, `Model`, `PrModel`, `Remote`, `Base`, `MaxCodeGroups`, `MaxDiffChars`, `Draft`, `NoPr`, `NoPush`, `Yes`, `Author`. Параметры командной строки всегда имеют приоритет над файлом. Например, при `"Draft": true` в файле все PR будут черновиками.

## Правила группировки файлов

Группы коммитятся в порядке из таблицы: сначала зависимости и инфраструктура, затем код, в конце документация.

| Группа | Файлы | Префикс коммита |
|---|---|---|
| Зависимости | `package.json`, lock-файлы, `requirements.txt`, `pyproject.toml`, `go.mod`, `*.csproj` и аналоги | `build(deps)` |
| CI и контейнеры | `.github/`, `Dockerfile`, `docker-compose*`, `.gitlab-ci.yml` | `ci` |
| Конфигурация | `*.config.js/ts/json`, `tsconfig*.json`, `.eslintrc*`, `.prettierrc*`, `.gitignore`, `.editorconfig` | `chore(config)` |
| Ресурсы | изображения, шрифты, аудио, видео, PDF | `chore(assets)` |
| Исходный код | всё остальное, отдельно по каталогам верхнего уровня (`src/components`, `src/pages` и т. д.) | `feat`, `fix`, `refactor` или `perf` (выбирает модель) |
| Стили | `*.css`, `*.scss`, `*.sass`, `*.less` | `style` |
| Тесты | `*.test.*`, `*.spec.*`, `tests/`, `__tests__/` | `test` |
| Документация | `*.md`, `*.txt`, `docs/`, `LICENSE`, `CHANGELOG` | `docs` |

Правила находятся в функции `Get-FileCategory` в файле `ai-flow.ps1`. Чтобы изменить их под свой проект, отредактируйте файл в папке проекта и выполните `install.ps1` ещё раз.

## Формат коммитов и pull request

Сообщения коммитов имеют вид `type(scope): subject`:

```
build(deps): update project dependencies
feat(components): add responsive navigation menu
style: adjust header spacing
docs: update installation guide
```

Тема пишется в повелительном наклонении (`add`, а не `added`), со строчной буквы, без точки в конце, не длиннее примерно 60 символов.

Pull request состоит из заголовка, раздела Summary (краткое описание от модели) и раздела Changes (список тем коммитов, собирается кодом без участия модели). Пунктов вроде «протестировано» в описании нет, потому что такие данные модель знать не может.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `aiflow` не распознаётся как команда | Терминал открыт до установки. Закройте его и откройте заново, в VS Code закройте окно целиком. Проверьте, что в PATH есть `%LOCALAPPDATA%\Programs\ai-flow`. |
| Не удалось проверить TLS-сертификат | Не установлен корневой сертификат Минцифры. Выполните `.\install.ps1 -InstallCertificate` или установите вручную (шаг 3). |
| Нет соединения с сервером | Проверьте интернет, VPN и антивирус. Порт 9443 должен быть доступен: `Test-NetConnection ngw.devices.sberbank.ru -Port 9443`. Если выход в сеть возможен только через прокси, запускайте с `-UseSystemProxy`. |
| HTTP 401, авторизация отклонена | Неверный или просроченный ключ. Получите новый в кабинете и выполните `aiflow -SetKey`. Проверьте, что ключ скопирован целиком. |
| HTTP 402 | Закончились токены или средства на балансе GigaChat. |
| HTTP 429 | Превышен лимит запросов. Бесплатный тариф работает в один поток. Скрипт повторяет запрос сам, при повторе подождите минуту. |
| Скрипт спрашивает ключ при каждом запуске | Переменная `GIGACHAT_AUTH_KEY` не сохранена или терминал открыт до её сохранения. Выполните `aiflow -SetKey` и откройте новый терминал. |
| `gh` не найден или не авторизован | Установите GitHub CLI и выполните `gh auth login`. До этого текст PR выводится на экран. |
| Коммит не создаётся, ошибка хука | Сработал pre-commit хук проекта (линтер, тесты). Исправьте замечания и запустите снова. |
| Нет изменений для коммита | В рабочей папке нет изменений относительно последнего коммита. |
| В коммитах странные сообщения | Модель иногда ошибается. Запустите с `-DryRun`, чтобы увидеть план до применения, или попробуйте `-Model GigaChat-2-Pro`. |
| `aiflow license`: не удалось загрузить текст лицензии | Тексты GPL, Apache, MPL загружаются с `api.github.com`. Проверьте доступ к GitHub, попробуйте `-UseSystemProxy` или выберите MIT, BSD, ISC, Unlicense (они работают офлайн). |
| README описывает проект неверно | Модель видит только дерево файлов и несколько фрагментов. Добавьте `description` в `package.json`, отредактируйте текст вручную или запустите с `-PrModel` другой модели. |
| `aiflow issue`: метки не применились | Таких меток нет в репозитории. Создайте их на GitHub или передайте существующие через `-Labels`. |
| Режим `-Stay` не работает | В состоянии detached HEAD он недоступен. Перейдите на ветку командой `git switch <имя>`. |
| Скрипт сообщает об остаточных файлах | Файлы изменились во время работы скрипта. Проверьте `git status` и закоммитьте их вручную. |

Для диагностики сети полезны команды:

Test-NetConnection ngw.devices.sberbank.ru -Port 9443
Test-NetConnection gigachat.devices.sberbank.ru -Port 443

## Безопасность и приватность

- **Ключ авторизации** хранится в переменной окружения пользователя и передаётся только на серверы Сбера. Он не записывается в файлы и не попадает в репозиторий. Если ключ утёк, выпустите новый в кабинете.
- **Код уходит во внешний сервис.** Для генерации сообщений модели передаются список файлов и усечённый diff (по умолчанию до 6000 символов на группу), для PR добавляется общая статистика изменений. Для README модель получает дерево файлов и фрагменты (до 60 строк, не более трёх файлов, `.env` и подобные файлы не читаются), для issue только вашу заметку, последние темы коммитов и список файлов верхнего уровня. Для лицензий, кроме встроенных, выполняется запрос к `api.github.com`, без передачи данных о проекте. Не используйте утилиту для репозиториев, содержимое которых нельзя передавать третьим лицам. Содержимое lock-файлов в запросы не включается.
- **Секреты в коде.** Если в изменениях есть пароли, токены или ключи, они попадут в diff, а значит, и в запрос. Не коммитьте такие файлы вообще, добавьте их в `.gitignore`.
- **Проверка сертификатов** включена по умолчанию. Параметр `-SkipCertCheck` отключает её на один запуск, не используйте его постоянно.
- **Принудительная отправка** (`--force`) не используется нигде.

## Обновление и удаление

Обновление: замените файлы в папке проекта на новые версии и снова выполните

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Файл настроек и ключ при этом сохраняются.

Удаление:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Uninstall
```

Установщик удалит папку с утилитой и запись из PATH. Переменная `GIGACHAT_AUTH_KEY` и файл настроек останутся. Удалить ключ можно командой

```powershell
[Environment]::SetEnvironmentVariable('GIGACHAT_AUTH_KEY', $null, 'User')
```

## Кроссплатформенная версия (Node.js)

Для Windows, macOS и Linux есть вторая версия утилиты на Node.js: [AI-Git-Flow-CLI](https://github.com/wildkodokushi/AI-Git-Flow-CLI). Она опубликована в npm, поэтому ставится без скачивания файлов:

```bash
npx ai-git-flow init              # мастер настройки: провайдер, ключ, модель, проверка
npm install -g ai-git-flow        # установить команду насовсем
```

После установки доступны команды `aigf` и `ai-git-flow`. Требуется Node.js 20 или новее.

| | PowerShell-версия (этот репозиторий) | Node.js-версия |
|---|---|---|
| Платформы | Windows | Windows, macOS, Linux |
| Установка | `install.ps1` из этого репозитория | `npx ai-git-flow init` или `npm install -g ai-git-flow` |
| Команда | `aiflow` | `aigf` (или `ai-git-flow`) |
| Модели | GigaChat | GigaChat, DeepSeek, Grok, OpenRouter, Groq, OpenAI, Ollama и любой OpenAI-совместимый API |
| Проверка модели | нет | `aigf doctor` |
| Требования | PowerShell 5.1 | Node.js 20+ |

Команды у версий разные, поэтому их можно держать на одном компьютере одновременно. Ключ GigaChat из переменной `GIGACHAT_AUTH_KEY` Node.js-версия подхватывает сама, повторно вводить его не нужно. Сертификат Минцифры, установленный в Windows для этой версии, Node.js не использует: мастер `npx ai-git-flow init` скачает его отдельно. Основное развитие идёт в Node.js-версии, эта остаётся простым вариантом «один скрипт без зависимостей».
